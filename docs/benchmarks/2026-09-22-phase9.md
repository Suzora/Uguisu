# Measurements — Phase 9 authentication and the API contract (2026-09-22)

Measured, not claimed. Phase 9 adds one deliberately expensive operation — a password verification — and one contract with a size worth knowing. Everything else it adds should cost nothing measurable, and this is where that is checked rather than asserted.

## Setup

| Item | Value |
|---|---|
| Machine | 4 vCPU Intel Xeon @ 2.80 GHz, 16 GB RAM (shared cloud container, no CPU pinning) |
| Build | `--release` for every figure on this page, including the server |
| Server | `uguisu serve --bind 127.0.0.1:<port>`, scheduler paused, `UGUISU_FEED_REFRESH_INTERVAL_SECS=86400` |
| Client | Python `http.client` over loopback, one connection per request (so every figure includes a fresh TCP connect) |
| Publisher | a local Python HTTP server standing in for the feeds |
| Method | argon2 via criterion, 20 samples; HTTP as 7 or 11 timed requests after the first, medians and ranges reported |

Two fixtures, both seeded through the public API:

| Fixture | Contents | Seeded in |
|---|---|---|
| **large** | 200 podcasts, 1 000 episodes | 341 s |
| **small** | 5 podcasts, 25 episodes | 8.8 s |

## argon2id, and why 64 MiB / 2 passes

`docs/SECURITY.md` §3.5 asks for roughly 100 ms per verification. Four parameter sets were measured before one was pinned:

| m | t | p | Median verification | |
|---|---|---|---|---|
| 19 456 KiB (19 MiB) | 2 | 1 | **18.0 ms** | RFC 9106's low-memory profile: four times too cheap |
| 47 104 KiB (46 MiB) | 1 | 1 | **43.1 ms** | still short, and one pass resists less |
| **65 536 KiB (64 MiB)** | **2** | **1** | **101.6 ms** | pinned |
| 65 536 KiB (64 MiB) | 3 | 1 | **139.0 ms** | more than asked for, for no stated threat |

Ranges: 17.9–18.1, 42.7–43.4, 100.9–102.5, 138.3–139.8 ms.

The pinned pair is a constant in `crates/uguisu-engine/src/auth.rs` and lives in the stored PHC string, so raising it later re-hashes on the next successful login. Hashing runs on `spawn_blocking` behind a **two-permit semaphore**: at most 128 MiB is committed to hashing at once, which is what keeps a login flood from becoming a memory exhaustion (`docs/SECURITY.md` §3.8).

Reproduce with `cargo bench -p uguisu-engine --bench argon2`.

## Login, end to end

30 successful logins, large fixture:

| | ms |
|---|---|
| p50 | **102.8** |
| p99 | **107.9** |
| min | 100.4 |
| max | 110.7 |

**The round trip is the hash.** 102.8 ms against a 101.6 ms verification leaves about 1.2 ms for the connection, the JSON, the session insert and the `Set-Cookie` — which is the intended shape: the cost is the control, not the plumbing. Three separate runs gave p50 101.3, 102.9 and 102.8 ms.

## The login limiter's boundary

Twelve wrong passwords from one address, fresh bucket:

| Attempt | Status | `Retry-After` |
|---|---|---|
| 1–10 | 401 `unauthenticated` | — |
| 11 | **429 `too_many_requests`** | **299** |
| 12 | 429 | 299 |

Exactly ten failures are free, which is the documented allowance, and the eleventh says how long to wait rather than "a few minutes". The ceiling on argon2 work from one peer is therefore ten verifications per five minutes — about one second of CPU.

## Authenticated request overhead

The cheapest route there is, so the difference is the authentication and nothing else. 11 requests each, large fixture:

| `GET /api/v1/health` | Median | Range |
|---|---|---|
| anonymous (no credential set) | **0.3 ms** | 0.3–0.4 |
| with a session cookie | **0.5 ms** | 0.4–0.7 |

**About 0.2 ms per authenticated request**, which is one indexed lookup on `auth_sessions.token_digest` plus a SHA-256 of 32 bytes. The hourly `last_seen_at` refresh means that lookup is a read on all but one request per hour per session, which is the point: the writer pool has size 1.

## The podcast list, after the cursor

`GET /api/v1/podcasts?limit=50`, 7 requests each:

| Fixture | Credential | Median | Range |
|---|---|---|---|
| 200 podcasts | none | **6.1 ms** | 4.9–10.4 |
| 200 podcasts | cookie | 6.8 ms | 5.2–7.7 |
| 200 podcasts | bearer | 6.5 ms | 5.1–8.0 |
| 5 podcasts | none | **1.6 ms** | 1.2–2.6 |

`GET /api/v1/status`: **1.8 ms** (200 podcasts, range 1.6–2.6) and **1.6 ms** (5 podcasts, 1.4–1.9).

Two things worth reading off that table. **The page costs what its 50 rows cost, not what the library costs**: 40× the podcasts is 4× the time, and the remainder is the fixed cost of the connection. And **`/status` no longer grows with the library at all** — 1.8 ms at 200 podcasts against 1.6 ms at 5 — because it counts rows instead of listing every podcast with its detail.

**Statement counts are counted from the source, not instrumented.** sqlx's statement log is not compiled into this build, so the numbers below are read off the code rather than measured, and are labelled that way:

| | Before Phase 9 | After |
|---|---|---|
| `GET /api/v1/podcasts` (page of 50, 200 podcasts) | 1 + 3N = **601** | **4** |
| `GET /api/v1/status` | 601 (it called the same lister for a `.len()`) | **1** |

What *is* measured is that the four statements use the indexes they were written for: `EXPLAIN QUERY PLAN` guards in `crates/uguisu-storage/src/{podcasts,fetches,archive_files,downloads}.rs` assert the plan names `idx_podcasts_page`, `idx_fetches_source`, `idx_sources_current` and `idx_episodes_sort`, and they fail if a query starts scanning. Those guards are the durable control; the timings above are the corroboration.

## The contract's size

| Artifact | Size |
|---|---|
| `docs/api/openapi.json` | 387 418 bytes — 74 paths, 83 operations, 188 schemas |
| `web/src/lib/api/generated/schema.d.ts` | 7 872 lines, 268 459 bytes |
| `web/src/lib/api/types.ts` | **89 lines**, down from 511 |
| `#[schema(value_type = …)]` overrides needed | **0** |

`schema.d.ts` contains 174 occurrences of `unknown`. 161 are `[name: string]: unknown` index signatures that `openapi-typescript` emits for every operation's parameter block, 9 are `application/octet-stream` response bodies (the media and artwork byte routes, where `unknown` is correct), and **2 are genuine**: `Episode.source_metadata` and `EpisodeExtras.value` are `serde_json::Value` in Rust — arbitrary JSON, for which `unknown` is the right TypeScript type. No named wire type resolved to `unknown` by accident.

Neither file is written by hand. `python3 scripts/check.py openapi api-types` regenerates and compares both, and `the_document_is_byte_stable` asserts two generations are identical.

## What is not measured here

- **Throughput and concurrency.** Uguisu is a single-operator archiver; a request-per-second figure would describe the loopback socket, not a bottleneck anybody has.
- **The frontend.** Phase 9 adds a login form and one header; the Phase-8 page timings are unchanged and not re-run.
- **The "before" statement counts.** The code that made 601 queries no longer exists to measure, so those figures are counted from the diff and labelled as counted.
