# Fuzzing — the feed parser, OPML and audio tags (2026-10-10)

The first cargo-fuzz runs of Uguisu's parsers, as [ADR 0065](../DECISIONS/0065-fuzzing-outside-the-workspace.md) sets them up. They found six ways a hostile audio file got past `uguisu-metadata`, all of them in `lofty` 0.25.4. The feed parser and the OPML reader gave up nothing. Each finding is fixed in Uguisu with a regression test. None is fixed or reported upstream.

## Setup

| Item | Value |
|---|---|
| Machine | AMD Ryzen 9 9950X3D, 8 logical processors, Windows 11 Pro 10.0.26300 |
| Toolchain | `nightly-2026-10-09`, cargo-fuzz 0.13.2, libfuzzer-sys 0.4.13 |
| Windows | x86_64-pc-windows-msvc with AddressSanitizer from MSVC 14.44 |
| Linux | the `rust:1.98.1-slim-trixie` image under Docker Desktop (WSL 2), AddressSanitizer, `-fork=1` with crashes, timeouts and out-of-memory kept going, all six targets at once |
| Corpus | what `fuzz/seeds` writes: the five silent containers of `uguisu-metadata`'s tests, bare and tagged, an RSS and an Atom feed, an OPML file; and `tests/fixtures/feeds/{parser,probe}` for the feed targets |

Reproduce with:

```bash
python3 scripts/check.py fuzz      # every target for 60 s; on Windows, the feed and OPML targets
```

On Linux, `check.py fuzz` keeps each finding's input in `fuzz/artifacts/<target>/`. A longer run of one target is `cargo fuzz run <target> corpus/<target> -- -max_total_time=300` from `fuzz/`.

- **Round 1** stopped three targets at their first finding.
- **Round 2** kept going and found the rest of what the old code had: 2 crashes and 9 timeouts in `identity_read`, 2 crashes in `tags_write`, and 467 in `opml_parse`, which were the target's own mistake (below).
- **Round 4** found 3 more in `tags_write`. Its 3 slow inputs in `identity_read` are the ADTS file, now given up on after 30 s.
- **Round 5** found no new bug; its 4 crashes were caught panics that libFuzzer's own panic hook turned into aborts. The metadata targets now restore Rust's default hook.

## Findings

| Found | Target | Input | What it did | Now |
|---|---|---|---|---|
| `lofty`'s ADTS reader seeks for ever | `identity_read` | 30 bytes | an import that met the file never finished | refused after the file's deadline (`f90e470`) |
| An Opus last-page granule position overflows `* 1000` | `identity_read` | 97 bytes | a panic with overflow checks on; without them, a division by zero can follow | caught, the file's error (`f90e470`) |
| A Musepack SV8 sample count overflows the same way | `identity_read` | 32 bytes | a panic | caught (`f90e470`) |
| A written FLAC or MPEG file does not parse again | `tags_write` | 1 495 and 32 bytes | nothing: the engine re-read the copy and discarded it | `write_tags` refuses it itself (`017e597`) |
| Junk with MPEG frame syncs behind an ID3 header reads as AAC once tagged | `tags_write` | 32 bytes | tagged, then every later write said "unsupported" | refused (`017e597`) |
| An M4A whose metadata handler atom claims the rest of its parent loses the values | `tags_write` | 841 bytes | reported written, read back nothing, and was written again on every sync | refused (`017e597`) |

The review of these fixes found two more in the same place:
- `lofty`'s MP4 writer recurses once per nested container atom. A file of 100 000 nested `moov` headers overflowed the stack, which no guard catches. Such an MP4 is refused before the write (`3d6b074`).
- The 30-second deadline covered a whole write, and `lofty` rewrites an entire MP4. The deadline grows with the file now, a second per 4 MiB (`3d6b074`).

**Not Uguisu's:**
- `opml_parse` first asserted that any outline survives a write and a read. An outline whose URL holds a NUL does not, because `write` leaves out what XML cannot carry, as documented. A stored URL never holds one, since a URL parser percent-encodes control characters. The target now writes the URLs an import could store.
- On Windows, the ASan runtime cannot unwind a Rust panic at all, so the metadata targets run on Linux only ([ADR 0065](../DECISIONS/0065-fuzzing-outside-the-workspace.md)).

**Upstream.** On 2026-10-10, `aac/read.rs`, `ogg/opus/properties.rs` and `musepack/sv8/properties.rs` on `lofty`'s `main` were byte for byte those of 0.25.4. Its tracker had no report of these three bugs. Nothing has been filed: a report goes out under a person's account.

## Not fuzzed

- The sidecars and manifests Uguisu reads back from the media root, and the Podgrab database an import opens.
- Discovery providers' JSON responses, the chapters document and artwork, which is checked by signature only.
- The HTTP client and its redirect policy: wiremock suites cover them.
- Every target ran for minutes, not hours. A longer run, and a coverage report, are left to the next one.
