# Risk Register

Likelihood and impact: L/M/H. Owner phase = where the mitigation must land. Review at the end of every phase.

| # | Risk | L | I | Mitigation | Owner phase |
|---|---|---|---|---|---|
| R1 | **Feed inconsistency** — broken dates, duplicate/empty GUIDs, rotating GUIDs, malformed XML, wrong MIME types | H | M | **Built:** tolerant parser with per-item isolation and typed `truncated`/`partial` (ADR 0017), dates with quality flags, identity cascade with the GUID-change rule (ADR 0006/0014), 19-feed corpus + probe fixtures + recorded live feeds, feed-rs differential and property tests; candidate duplicates surfaced, never merged. Residual: rewritten GUIDs on a whole feed produce one candidate per episode, each resolved by one command or click (ADR 0051) | 3 |
| R2 | **Provider API instability** — Apple changes/limits the keyless API; Podcast Index changes auth or limits | M | M | Provider abstraction; spec and recorded fixtures kept apart so schema drift shows up as a diff; per-provider health and circuit breakers (built); fail-fast provider retries; resolver works without providers; keys are the user's own; live 2026-09-17: Apple did not throttle 45 req/20 s, gpodder.net publishes no subscriber counts | 2 |
| R3 | **Provider availability / terms** — a provider goes offline or forbids caching | M | L | Discovery ≠ archival; every provider can be turned off; cache TTLs configurable per kind (search, lookup), never longer than a provider's `Cache-Control` allows; the providers' terms re-read in Phase 11 | 2, 11 |
| R4 | **SSRF via feeds, redirects, provider results** | M | H | Single HTTP crate with pre-connect address checks and per-hop redirect validation (ADR 0011); tests with private-address redirects | 2 |
| R5 | **Metadata format compatibility** — `lofty` edge cases, chapter frames, huge artwork | M | M | **Built:** a capability table per container *and* field, so a field a format cannot hold is reported `not_embeddable` and kept in the sidecar rather than lost; a write starts from a clone of the existing tag and touches only the thirteen managed keys; a container Uguisu does not tag is a result, not a failed batch; artwork capped at 16 MiB and validated by signature. Two findings came out of building it: ID3v2's `PCST` frame made the *whole* frame set fail to encode, and four fields did not survive a write-then-read — both were removed from the managed set rather than shipped, because a field that does not round-trip moves the archive's hash on every run (ADR 0026). No `.bak`: the file is copied, tagged, re-read and only then renamed over the original, so the original *is* the backup until the replacement is proven readable. Residual: chapters are not written at all — `lofty` exposes them only through its ID3v2-specific API and not for MP4, and the chapters document is a URL nothing fetches (ADR 0026) — and `cargo fuzz` targets for the tag reader are still open | 6 |
| R6 | **Filesystem edge cases** — Windows reserved names, path length, case-insensitive collisions, Unicode normalization differences, non-UTF-8 paths on Linux | H | L | **Phase 5 (as built):** per-segment sanitization in three profiles (`windows`/`posix`/`portable`, the default being the intersection); device names escaped *inside* the name so escaping is idempotent; control, bidi and zero-width characters dropped; trailing dots and spaces trimmed; drive-letter prefixes rewritten; NFC normalization; 120 characters and 200 UTF-8 bytes per segment and 200 characters per path with deterministic truncation that keeps the extension; containment decided component-wise and after symlink resolution. Property tests run the whole pipeline over traversal strings, mixed separators, UNC and absolute forms, device names, NUL and bidi overrides and full-width confusables on all three profiles. **Phase 11:** `crates/uguisu-archive/tests/filesystem.rs` creates every hostile name, with its sidecar and scratch name, on the file system the tests run on and reads it back; on ext4 it found that a long CJK title made a name Linux refuses (over 255 bytes), and segments are now cut at 200 bytes too. Residual: two titles that differ only in case are one name on NTFS and APFS; an import, a relocation and a newly queued download see that and take another name, but of two downloads queued before either file exists the later ends `target_exists` until a retry, which renders its target again. Nothing is overwritten (`case_variant_titles_never_overwrite`) | 5 |
| R7 | **SQLite scalability** at 500k+ episodes and large event logs | M | M | Keyset pagination on `(sort_at, id)`, covering indexes, JSON side tables, event retention applied by the daily maintenance tick (30 days or 100 000 rows by default), chunked batch writes; measured 2026-09-17: 10k-item import 2.9 s, forced identical refresh of 10k 0.64 s, 18 MiB for 10k episodes (`docs/benchmarks/2026-09-17-phase3.md`); 500k-episode listing still to be measured in Phase 11; inserts are single-row, and multi-row inserts wait for that benchmark | 3, 11 |
| R8 | **Download reliability** — servers without range support, changing ETags, CDNs returning HTML error pages with 200, disk full | H | H | **Built:** resume only with `Accept-Ranges` and a strong validator, a `206` verified against the requested offset, a `200` after a Range request restarting instead of appending, `416` handled, prefix re-hashed before continuing (ADR 0019); length check against `Content-Length` with an identity-encoded client; container sniffing recorded; ENOSPC and a pre-flight space check pause the whole queue persistently and refund the attempt; typed attempt log; scenario server with 18 hostile routes plus kill-and-restart and SIGTERM tests. Residual: a host that silently serves different content under an unchanged strong ETag cannot be detected, because the recorded hash covers the bytes that arrived and verification agrees with them; Windows rename under antivirus is retried five times and then fails the job typed (`finalization`) | 4 |
| R9 | **Concurrency bugs** — job double-processing, lost updates, deadlocks between scheduler and workers | M | H | **Built:** single-writer DB discipline (`BEGIN IMMEDIATE` writer pool of 1, data-directory lock, per-podcast refresh coalescing — ADR 0016), one job row per episode, every worker write a compare-and-set on the expected state, user commands writing the database before cancelling the token, a claim that never awaits a host permit while holding a global slot, a shutdown that stops the scheduler before cancelling, and a pure transition table with property tests (ADR 0018). Found and fixed this way: a user retry reset `attempt_count` and the re-inserted `attempt_no` collided with the unique index, wedging the queue; the attempt log now numbers itself | 3, 4 |
| R10 | **Feed URL changes** creating duplicate podcasts or losing history | L | M | **Built:** `podcast_sources` history, permanent-redirect and `new-feed-url` detection, same-show verification (GUID, title + episode overlap) before an atomic source switch, unverified announcements reported and retried, redirects to another show refused before any write, `conflict` on adding a second feed with a known GUID. **Phase 10:** an unverified announcement is kept and shown, and a person moves the podcast to it, or to any feed URL, with the history kept and a move onto another podcast's feed refused (ADR 0052). Residual: a forced move onto a different show is possible, recorded and reversible, never automatic | 3, 10 |
| R11 | **Cross-platform packaging** — WebView2 bootstrapper failures, WebKitGTK rendering gaps, Flatpak sandbox blocking the archive folder | M | M | Tauri smoke tests per platform in CI: the unpackaged binary on every pull request ([ADR 0063](DECISIONS/0063-ci-within-five-minutes.md)), the installed packages on a tag or by hand ([ADR 0046](DECISIONS/0046-ci-within-a-minutes-budget.md)); portals for folder access; documented permissions; AppImage fallback | 9a, 9b |
| R12 | **Scope creep toward a player/streaming app** | M | M | `PRODUCT.md` non-goals; every phase asks "why migrate"; minimal player only | all |
| R13 | **Own feed parser bugs** (ADR 0008) | M | M | Differential tests against `feed-rs` on corpus and live feeds, 200-case property tests (arbitrary bytes and XML-ish text never panic, generated feeds parse deterministically), limits tested; structured fuzzing (`cargo fuzz`) still open | 3 |
| R14 | **Desk-research facts wrong** (limits, endpoints, ToS captured without live access) | M | M | Primary sources (Apple docs, Podcast Index OpenAPI + ToS, mygpo docs) read in Phase 2 Part A; providers built strictly against them; Part B (2026-09-17) verified Apple, gpodder.net, the resolver and SSRF live and recorded fixtures (`tests/fixtures/discovery/live`), finding three mapping errors that are fixed; **residual:** Podcast Index authenticated responses unverified until a user key is available | 2 |
| R15 | **Data loss through user-facing destructive operations** | L | H | No automatic deletion; the two commands that delete library rows nothing can recreate, `episode resolve --same` and `podcast remove --yes`, take that explicit flag and are logged as events, and a removal keeps every file (ADR 0055); `uguisu db backup` copies the database while it is in use (ADR 0056). **Phase 4:** the downloader deletes nothing — an occupied target fails the job typed, an unknown `.part` is only reported, a vanished file is only counted by a deep reconcile — and a final path is created solely by renaming a complete, hashed and fsynced file (power-cut safe on Unix via a directory fsync; Windows has no directory fsync, so a crash in that window leaves the `.part`, which recovery finalizes). **Phase 5:** still nothing deletes media. Verification is read-only by rule, not by accident: it never writes, truncates, renames or repairs, so a file edited in place is reported `invalid` and left as the user left it, and a file that is gone keeps its record and hash so it can be recovered. Relocation is a rename only, refused across devices and refused onto an occupied path, and a record update the unique path index rejects moves the file back. **Phase 6:** the rule held through six new write paths — leftover scratch files, unknown sidecars, unknown media, a foreign file at a target, an import source, a superseded artwork image and a conflicting record are all reported and kept. Import copies and never moves, opens the source read-only (a test hashes the tree before and after) and refuses to overwrite an existing file. Tag writing never modifies the only copy. There is no `.bak` anywhere, and the sketch that promised one is withdrawn rather than left as a claim: a copy-then-rename leaves no moment at which a `.bak` would help. **Phase 10:** what is kept is now also listed: `archive orphans` reports leftovers, orphan parts, unknown media and stray sidecars, and still deletes nothing (ADR 0051) | 4, 5, 6, 7 |
| R16 | **Dependency/supply-chain issues** (advisories, license changes) | M | M | `cargo deny` in CI; lockfiles committed; minimal dependency set | 1 |
| R17 | **Single-maintainer providers** (fyyd, gpodder.net) disappearing | M | L | Opt-in, low priority, fixtures keep tests green | 2 |
| R18 | **Large-archive verification time** (TBs on HDD) | M | L | Light verification (mtime/size) by default, full on demand (`archive verify --full`), never scheduled; algorithm-tagged hashes allow BLAKE3 later (ADR 0007) | 5 |
| R19 | **Automatic archiving fills a disk** — a policy that queues without being asked can exhaust storage overnight | M | H | Off by default (`UGUISU_ARCHIVE_AUTO_DOWNLOAD=false`), so a default installation archives nothing on its own; opt-in per podcast or globally; `max_backlog` counts *outstanding* work, not what one evaluation queued, so repeated refreshes cannot top the queue back up past the limit; an age limit bounds a first sync of a long back catalogue; the existing `min_free_bytes` check pauses the whole queue with `disk_full` before the disk is full. Residual: the limits count episodes, not bytes, because a reliable size is not known before the download | 5 |
| R20 | **A file imported under the wrong episode** — a foreign archive's names are all Uguisu has, and a misplacement is quiet and permanent | M | H | **Built:** a deterministic score over five signals with a documented weight table; a candidate must reach 85 **and** beat its runner-up by 10, so two episodes that explain a file equally well produce `ambiguous`, never a guess; a numeric disagreement penalizes and a date disagreement caps the score; a per-directory podcast gate keeps a file from being scored against the wrong show at all; the plan is printed before anything is copied and `--apply` is required. A wrong import is worse than an unresolved one, so every borderline case is a line in a report. Residual: the thresholds are constants tuned against a fixture matrix, not against a real user's archive, and an import of a very large tree into a very large show is O(files × episodes) scoring (≈1.8 s per 500 files against 1 000 episodes) | 6 |
| R21 | **A tag write damages the archive** — the one operation that rewrites media a user already has | L | H | **Built:** the file is never modified in place. It is copied, tagged, re-opened, re-parsed, re-hashed and only then renamed over the original; `clippy.toml` forbids `lofty`'s in-place API workspace-wide so the safe path cannot be bypassed by accident; the record must already match the file before anything starts; `tag_state = pending` is committed *before* the first byte moves, so a crash is resolved by hashing rather than by guessing; the write is idempotent, and a second run in the same mode opens nothing for writing. Residual: tagging is an explicit command and is never run automatically, which is a safety property and also means an archive is only as tagged as someone asked for | 6 |
| R22 | **The scheduler hammers a publisher** — a refresh loop is the first thing in Uguisu that makes requests nobody asked for, and a bug in it is other people's bandwidth | M | H | **Built:** automatic refreshes use the same HTTP stack, SSRF policy and conditional requests as manual ones, so `ETag`/`If-Modified-Since` and body fingerprints still stop a 304 from costing a parse; the interval is never shorter than the origin's `Cache-Control: max-age` and the deterministic spread is **one-sided**, so a spread can never pull a fetch earlier than the origin allowed; a 60-second floor sits under every start, so a podcast whose refresh fails before the pipeline can write a back-off cannot spin; failures back off exponentially to 24 h; both interval keys refuse anything below 60 s; per-podcast and global pause stop it entirely. Residual: a user who sets a 60-second interval on a thousand podcasts gets what they asked for | 7 |
| R23 | **A restart stampedes** — an installation that was off for a week comes back with everything overdue at once | M | M | **Built:** the due query is `ORDER BY … LIMIT capacity`, so a drain is a queue bounded by `UGUISU_FEED_REFRESH_CONCURRENCY`, and every drained podcast is replanned in catch-up mode across a whole interval — so the library de-correlates after one pass instead of re-synchronising into one window. Tested with six podcasts a week overdue. Residual: the first pass after a long outage is still the busiest one | 7 |
| R24 | **A stored setting bricks the daemon** — the settings table is the first thing that can make the engine refuse to start, and the API that would fix it is behind that start | L | H | **Built:** a stored value that no longer parses is quarantined, not fatal and not deleted — the engine opens without it, a warning names it, a `settings.rejected` event records it, and `config validate` prints it with the parser's message. Six keys (two secrets and the address they are sent to, two directories, the SSRF allowlist) can never be stored at all, so a settings write can never widen the network policy, redirect a secret or move the database. Residual: a quarantined key silently runs on its default until somebody reads the warning | 7 |
| R25 | **The browser becomes the second place that decides things** — a UI that reimplements a state machine, a policy or a validator drifts from the engine and is wrong in the cases that matter | M | H | **Built:** every state name, ranking, policy evaluation and settings validation stays in Rust; the browser has one typed API layer and no store mirroring the database ([ADR 0034](DECISIONS/0034-web-ui-architecture.md)); every mutation ends in an authoritative re-read, and the event stream is an overlay whose every reconnect forces one ([ADR 0033](DECISIONS/0033-sse-reconnection.md)). Phase 9 removed both reasons the browser had to compute: the podcast list endpoint takes parameters and a cursor, and job rows carry their own titles ([ADR 0040](DECISIONS/0040-one-cursor-contract.md)). Residual: the library view reads every page and filters client-side over the whole list, because rewriting it to page server-side is a UI change nobody has asked for | 8, 9 |
| R27 | **The API is exposed without a password** — the loopback default was a convention, not a control, and `--bind 0.0.0.0` used to start silently with the same log line | M | H | **Built:** a non-loopback bind with no credential is a startup failure with exit code 12, checked before the listener opens and before the workers start; the override is one deployment knob that cannot be set through the API it protects, and it logs a `WARN` naming the address and `auth = "disabled"` ([ADR 0037](DECISIONS/0037-exposure-gate.md)). Phases 2 and 3 of `scripts/e2e.py` assert the refusal's exact first line, all three of its hints and the override's warning. Residual: the override exists, deliberately — a control nobody can override is a control people work around by patching the binary | 9 |
| R28 | **A credential leaks through a log, a URL or a process listing** — the first phase in which Uguisu holds a secret at all | M | H | **Built:** a password is read from a terminal without echo or from stdin, never from an argument or an environment variable; `Secret<T>` wraps every credential-carrying field, and comparison goes through one constant-time path; the session cookie exists in the database only as a digest, and a token only as a digest; no route accepts a credential as a query parameter, and a test asserts the classifier reads none; `scripts/e2e.py` greps everything the server and the CLI wrote for the password and both token secrets. Residual: a `write` token in a CI environment is as good as the password for everything except changing the password, which is what scopes and revocation are for | 9 |
| R29 | **The API contract drifts from the API** — a document or a generated client that stops matching the code is worse than none, because it is believed | M | M | **Built:** the document is derived from the Rust types and the TypeScript from the document, both committed and both checked in CI; two tests read the router's own source and fail if a route is undocumented or an operation unrouted; one holds each operation's declared security against the authorization classifier; one fails if two types would collide into a single schema name ([ADR 0039](DECISIONS/0039-openapi-from-the-types.md)). Residual: `#[utoipa::path]` still has to be written per handler, and a handler added with no annotation is caught by the coverage test rather than by the compiler | 9 |
| R26 | **Feed text reaches the DOM** — titles and show notes are publisher-controlled, and the UI is same-origin with an unauthenticated API | M | H | **Built:** every field is rendered as text (`description_text`, never `description_html`), and there is no `{@html}` anywhere in `web/src` — a grep is the whole audit, and Svelte escapes interpolation by construction. Archived bytes cannot execute either: the recorded `Content-Type` is never echoed but canonicalised to one of thirteen media types or `application/octet-stream`, with `nosniff` on every response ([ADR 0032](DECISIONS/0032-media-and-artwork-over-http.md)). Phase 9 added the authentication this row's residual named: the API is authenticated, the CSP is served rather than promised, and there is no CORS for another origin to use. Residual: a local process with the operator's cookie or token can do what the operator can, which is what a single-operator design means | 8, 9 |
| R30 | **CI outgrows five minutes** — a slow pull-request run is waited out or skipped, and a red one is then merged anyway | M | M | **Built:** every job starts at once behind one `ci` check; the tests run under cargo-nextest in two halves; Windows runs a reduced set on a pull request; caches are saved from `main` and kept warm by a run twice a week; a timeout on every job, enforced by `check_needs.py --workflow`; the rule that no pull-request job takes more than 4.5 minutes cold ([ADR 0063](DECISIONS/0063-ci-within-five-minutes.md)). Residual: a cold run follows every toolchain change and every Rust update on the runner image, and a run that overlaps another queues behind GitHub's 20 concurrent jobs | 9b |
| R31 | **A Windows-only defect reaches `main`** — the whole suite runs on Windows only after the merge, and the defects Windows found so far were in file locking, renames, the database backup, a thread's stack, Ctrl-Break and the temporary directory | M | M | **Built:** on a pull request Windows runs clippy, the CLI smoke, the binaries with `#[cfg(windows)]` tests and the desktop shell; `win-test-full` runs the rest on every push to `main`, and a red `main` is fixed before the next merge ([ADR 0063](DECISIONS/0063-ci-within-five-minutes.md)). Residual: a defect in the rest is found minutes after the merge rather than before it | 9b |
