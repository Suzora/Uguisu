# Security and Threat Model

Uguisu is self-hosted and often runs on a home network, but it fetches arbitrary URLs on behalf of users, writes files to disk from untrusted input and exposes an HTTP API. This document lists assets, trust boundaries, threats and the controls Uguisu commits to. It is reviewed as a release gate (Phase 11).

Report vulnerabilities privately through GitHub's private vulnerability reporting (<https://github.com/suzora/uguisu/security/advisories/new>); do not open public issues for exploitable bugs.

## 1. Assets

- The **archive** (media files, sidecars) — integrity and availability.
- The **database** and configuration (including provider credentials, API tokens, password hash).
- The **host network** reachable from the Uguisu process.
- The **host filesystem** outside the archive root.

## 2. Trust boundaries

| Boundary | Trusted side | Untrusted side |
|---|---|---|
| Browser/CLI ↔ API | authenticated admin | anyone who can reach the port |
| Web UI ↔ feed content | Uguisu's own markup | every title, subtitle and show note a publisher wrote |
| Uguisu ↔ feeds, enclosures, websites | Uguisu | any publisher, any URL a user pastes |
| Uguisu ↔ discovery providers | Uguisu | provider responses (may be wrong or malicious) |
| Uguisu ↔ filesystem | archive root | file names derived from feed content; imported archives |
| Uguisu ↔ subscription lists | Uguisu | every outline and URL of an OPML file from another app |
| Desktop shell ↔ local server | Tauri process | other local processes |

## 3. Threats and controls

### 3.1 Server-side request forgery (SSRF)

**Phase 7 note:** automatic refreshes go through exactly the same `uguisu-http` stack, the same policy and the same redirect re-validation as a manual `podcast refresh` — the scheduler calls `Engine::refresh_podcast` and opens no network path of its own. The allowlist (`UGUISU_HTTP_ALLOW_PRIVATE_HOSTS`) is one of the six keys that may never be stored in the database, so a settings write can never widen the network policy ([ADR 0028](DECISIONS/0028-persisted-settings-and-precedence.md)).

*Threat:* a pasted URL, a feed enclosure, an `itunes:new-feed-url`, a redirect, a URL given to `podcast move-feed` or a provider-supplied feed URL points at `http://169.254.169.254/`, `http://localhost:…`, a router admin page or an internal service.

*Controls (all in `uguisu-http`, no other crate builds an HTTP client — enforced by `cargo deny`; **implemented in Phase 2**):*
- Only `http`/`https` schemes; ports 80, 443 or ≥ 1024. No setting changes this, and the port rule also applies to allow-listed hosts.
- Host names that always mean "local" (`localhost`, `*.localhost`, `*.local`, `*.internal`, `*.home.arpa`, `*.lan`, `*.intranet`, `*.onion`, single-label names) are refused.
- Literal IPs are classified (loopback, RFC 1918, CGNAT, link-local, unique-local, multicast, unspecified, broadcast, documentation/benchmarking/reserved ranges); IPv6 addresses embedding IPv4 (mapped, compatible, NAT64, 6to4, Teredo) are classified by the embedded address. Decimal, octal, hex and shortened IPv4 spellings are canonicalized by the URL parser before the check.
- Layer 1: the host is resolved before connecting and every address is classified. Layer 2: a `reqwest` DNS resolver hook returns only policy-approved addresses, so a name that rebinds between validation and connection still cannot be reached. `HTTP_PROXY`, `HTTPS_PROXY` and `ALL_PROXY` are ignored: through a proxy the proxy would resolve the name and this layer would not be asked (`crates/uguisu-http/tests/no_proxy.rs`).
- Redirects are never auto-followed; each hop is re-validated; max 5 hops; when the origin changes (scheme, host or port), only the caller's `Accept` header goes along, so no credential does, under whatever name (`Authorization`, `Cookie`, Podcast Index's `X-Auth-Key`).
- Optional admin allow-list (`UGUISU_HTTP_ALLOW_PRIVATE_HOSTS=nas.local`) for intentional LAN feeds, off by default; a `Trusted` profile exists only for the user's own Uguisu server address used by the CLI.
- Size caps: provider responses 2 MiB; feeds `UGUISU_FEED_MAX_BYTES` (50 MiB by default); an HTML page fetched while resolving a URL shares the feed client's 50 MiB cap (`Profile::Html` is defined but unused); plus timeouts; streaming reads with early abort; cancellation tokens.
- Bodies are sniffed (`uguisu_feed::probe`), not trusted by `Content-Type`.
- **Media downloads use the same policy** (Phase 4): an enclosure URL is an untrusted URL like any other. A private, loopback or link-local enclosure, and a redirect to one, fails the job `not_retryable` with `policy_blocked` before a connection is made — no request, no `.part` file, no retry. A URL with no host or no known port (`file:`, `data:`, `mailto:`) is refused at enqueue time; any other non-`http(s)` scheme (`ftp:`, `ws:`) is queued and fails its first attempt `not_retryable` with `policy_blocked`. Media transfers are streamed with a byte cap and an idle timeout, so a slow-loris or endless body cannot hold a worker or memory.
- **Artwork uses the same policy** (Phase 6): a podcast image URL comes out of a feed, so it is an untrusted URL like any other. It is fetched through a new `Profile::Artwork` — 16 MiB cap, `Accept: image/*` — which inherits the two-layer check, the manual redirect walk and the byte caps unchanged. No second URL validator was written, and no `Trusted` profile is involved; a blocked host fails the fetch with `blocked_by_policy` (exit 6, as for a feed), `podcast.artwork.failed` carries the reason `policy`, and the podcast keeps whatever image it had.
- Tests: IPv4/IPv6 classification tables, obfuscated literals, redirect-to-private/link-local/loopback, allow-list behaviour, resolver refusal of `localhost`; `crates/uguisu-download/tests/security.rs` asserts the download-side behaviour end to end. The artwork fetch has its own: `crates/uguisu-engine/tests/archive_assets.rs` `private_artwork_address_is_refused` points a feed's artwork at the cloud metadata address and expects `blocked_by_policy`.

### 3.2 Path traversal and filename attacks

*Threat:* titles like `../../etc/cron.d/x`, reserved Windows names (`CON`, `NUL`), trailing dots/spaces, NUL bytes, RTL override characters, over-long paths, case-collisions on case-insensitive filesystems.

*Controls (in `uguisu-archive`):*
- Templates produce path **segments**; every segment is sanitized independently (per profile: `windows`, `posix`, `portable`), never interpreted as a path.
- Separators become `-` and a segment of only dots is dropped; a reserved device name is escaped before its extension (`nul.mp3` → `nul_.mp3`); control, bidi and zero-width characters are removed (a newline or tab becomes a space); Unicode NFC; length limits per segment and per full path (with deterministic truncation that keeps the extension and identity suffix).
- The deepest existing ancestor of the joined path is canonicalized and must stay inside the canonical root (`resolve_checked`). The download queue checks its paths lexically (`uguisu_download::paths::resolve`): plain components under the media directory, with no symlink resolution. Anything else is refused: a rendered destination falls back to the identifier layout (`docs/ARCHIVE_ENGINE.md` §7), and a stored path that leaves the root fails the job (`validation`).
- Extensions come from a whitelist of declared media types or a short alphanumeric URL suffix (Phase 4, below), never from a title.

**Phase 5 (as built):** feed text now reaches path components, so the controls above are load-bearing. What is actually implemented, in `uguisu-archive` (ADR 0022, `docs/ARCHIVE_ENGINE.md` §4–§6):

- **Segments, never paths.** A template's `/` separates components; a value's `/` or `\\` becomes `-`. A value can therefore never add a component, which a property test asserts directly.
- **Per-profile sanitization.** Control, bidi and zero-width characters dropped; the Windows character set and reserved device names handled under `windows` and `portable`; trailing dots and spaces trimmed; a name of only dots dropped; a `C:` prefix rewritten; NFC normalization; 120 characters and 200 UTF-8 bytes per segment and 200 characters per path, with deterministic truncation that keeps the extension.
- **Idempotent escaping.** Sanitizing an already sanitized segment returns it unchanged — a device name is escaped inside the name (`nul.mp3` → `nul_.mp3`), not appended to the end — so a path read back from the database and re-checked does not drift. The 120-character cut happens *last* and the tail is trimmed again after it, because cutting a long name can re-expose a trailing dot or space that the first trim removed; Windows would drop it silently and the stored path would name a file that does not exist. The property suite found that case during Phase 6 and it is now pinned by a unit test.
- **Component-aware containment, never a string prefix.** `/media/podcasts-evil` starts with `/media/podcasts` as text and is a different directory; comparison is component by component and rejects any `..`.
- **Symlink-aware resolution.** The deepest existing ancestor is canonicalized before a path is used, so a symlinked directory planted inside the archive cannot point out of it. A symlink standing in for the artifact itself is never opened: it is `invalid`, with `not_a_file` when it points inside the root and `outside_root` when it points out of it.
- **The same check everywhere.** A rendered path, a stored archive path and a relocation target pass through `resolve_checked`. The download queue checks a proposed destination and its stored target and `.part` paths with `uguisu_download::paths::resolve`: plain relative components under the media directory, compared by component, with no symlink resolution. The queue treats its `DestinationResolver`'s answer as untrusted input.
- **Read-only where it should be.** `path-preview` reads the disk only to check whether a path is taken, and writes nothing; verification never writes to the file it checks; nothing in Phase 5 deletes a media file.

Property tests run the whole pipeline over traversal strings, mixed separators, absolute and UNC forms, drive letters, device names, NUL and bidi overrides, full-width confusables and 200-character values on all three profiles, asserting that the result is relative, stays under the root, has no traversal component and renders identically twice. `crates/uguisu-archive/tests/{paths,security}.rs` hold these.

**Phase 4 (as built, still true):** `part_path` remains `<podcast-id>/.uguisu-tmp/<job-id>.part` — ULIDs only — so the temporary file never carries feed text and finalization stays an intra-filesystem rename. Extensions come from a whitelist of media types or a lowercase alphanumeric URL suffix of at most five characters. `target_path`/`part_path` are stored relative to the media directory, so the archive can be moved without a database rewrite.

**Phase 6 (as built):** Phase 6 reads paths it did not write — from sidecars, from manifests and from a foreign archive — so every one of them is untrusted input:

- **A path inside a document is parsed, never trusted.** A manifest line that is absolute, contains `..` or names a `.uguisu` component is refused as `path_invalid`, and a repeated path as `manifest_invalid`. A sidecar's own `archive.relative_path` is never used: a rebuild takes the location from where the sidecar lies, and reports one whose recorded path is absolute or contains `..` as malformed. The resulting relative path still goes through `resolve_checked`, so a poisoned document cannot reach outside the media root even if the parser were wrong.
- **`.uguisu` cannot be shadowed.** The control directory at the media root is reserved, and `sanitize::segment` escapes any segment that would render it (`.uguisu` → `._uguisu`), so no podcast or episode title can produce a directory that a later scan would skip — or that would let a media file be written where a manifest belongs.
- **Scans never follow links.** The rebuild scan and the import scan both walk with `follow_links(false)`, record a symlink as a `Symlink` finding and move on. An import source is additionally required to resolve inside its declared import root, and a root that overlaps the media directory is refused outright — importing Uguisu's own archive into itself is not a supported operation.
- **Nothing is read whole to decide about it.** A scan reads a file's size and its first 16 bytes; a sidecar is read only up to 256 KiB and refused above it, a manifest only up to 64 MiB, so a huge file with either name costs one byte past the cap; artwork is capped by `UGUISU_ARCHIVE_ARTWORK_MAX_BYTES` (default 16 MiB, also a stored setting), which the fetch passes in place of `Profile::Artwork`'s cap. An import then reads each media file's tags and audio properties through `lofty`, read-only, cover art skipped, within its 16 MiB per-item cap, and a layout's side files up to 64 KiB; it hashes a whole file only to compare it with bytes already archived or with a twin in the same run, and when copying it.
- **Another tool's database is read, never written (Phase 10).** Podgrab's `podgrab.db` is opened read-only and immutable, with `query_only` on and `trusted_schema` off, and refused while a `-journal` or `-wal` lies beside it, so a running Podgrab is never read mid-write and no lock file is ever created in its directory. Its path is validated like an import root's and is as privileged: on the server it names a file on the server's machine.
- **The web UI sends a typed server path, nothing more (Phase 10, ADR 0059).** The import page carries the folder and Podgrab's database exactly as the operator typed them, in the JSON body of a mutation that needs a write credential and is refused from another site (ADR 0058). No route lists directories. A dry-run import still names every media file under the folder it is given, and its error says whether a path exists, so a write credential can enumerate media files anywhere the server can read; a path that does not resolve answers `import_source_invalid` naming the path as typed; a file, or a folder overlapping the media directory, is named by its resolved path.
- **A restore reads a folder the way an import does (ADR 0060).** `archive restore` names a server path, walks it without following links, refuses the media directory, and uses a file only when its SHA-256 equals the record's. It lands the copy with a rename that never replaces, so a file at the record's path is kept. A redownload is refused while anything is at that path.
- **Bytes decide what an image is.** The signature must be JPEG, PNG or WebP, and a declared `Content-Type`, unless absent or `application/octet-stream`, must name the same format; the extension is never trusted; an SVG, an HTML error page or an ELF binary advertised as `image/png` is refused. Embedding into audio tags validates the picture a second time on the way in.
- **Ambiguity is never resolved silently.** An import match below the threshold, or inside the margin of its runner-up, is reported and not imported. A wrong import is worse than an unresolved one.

**As built:** an import root, a restore folder and a Podgrab database name paths on the server's machine. Once a password is set, an import is a mutation and needs a `write` credential (§3.5); without one, `uguisu serve` refuses a bind beyond loopback unless the override is set (§3.6).

### 3.3 Malicious or broken feeds

*Threat:* XML bombs (billion laughs), external entities, gigantic feeds, deeply nested elements, invalid UTF-8, script in HTML descriptions.

*Controls:* `quick-xml` with entity expansion disabled and no DTD/external entities (only the five predefined XML entities, nine fixed HTML entities (nbsp, hellip, mdash, ndash, lsquo, rsquo, ldquo, rdquo, copy) and numeric character references are resolved; nothing a DTD declares is; the billion-laughs fixture is parsed in milliseconds with the entity left unexpanded — Phase 2 probe and Phase 3 parser alike); the feed body cap (`UGUISU_FEED_MAX_BYTES`, 50 MiB) is enforced by the HTTP client while reading, so an oversized body is never held in memory, and again by the parser; depth limit 64; item cap 50 000 (`truncated`, not an error); per-node text cap 64 KiB, per-field cap 4 KiB, 16 enclosures and 64 raw extensions per item, at most 100 isolated malformed items; lossy UTF-8/UTF-16/Latin-1/CP1252 handling with warnings; a single malformed item is isolated, a malformed document fails the refresh without touching stored data (ADR 0017); fetch, verification fetch and parse run under UGUISU_FEED_REFRESH_TIMEOUT_MS (60 s) with cancellation; persisting the result runs outside it; HTML in descriptions is stored verbatim beside a plain-text rendering (`description_text`), and the SPA shows only the plain text (§3.4a). Redirect targets that are a different podcast are refused before any write (`docs/FEED_ENGINE.md` §8), so a hijacked or expired domain cannot inject another show's episodes into an archive.

**OPML (Phase 10, [ADR 0049](DECISIONS/0049-opml-import-and-export.md)):** an imported subscription list is parsed with the same reader settings — no DTD, no custom entities, an entity bomb left as literal text — and capped at 1 MiB (checked by the CLI before it reads further and by the parser), 64 levels and 10 000 feeds. Its URLs are untrusted: the plan only compares them with the library and sends nothing; applying resolves each through the SSRF stack of §3.1, exactly as a pasted URL, and adds only a feed the URL served itself, so a list cannot quietly turn a web page into a subscription. Importing is a mutation (a read token cannot), and nothing in it writes a file. An export carries every feed URL as stored, including a private feed's token: treat the file like the database.

### 3.4 Malicious media files

*Threat:* crafted MP3/MP4 metadata that exploits tag parsers; polyglot files.

*Threat (Uguisu adds):* Uguisu now *writes* into those containers, so a crafted file could also be a way to make Uguisu destroy media it was asked to annotate.

*Controls:* tag parsing in memory-safe Rust (`lofty` 0.25), never shelling out to ffmpeg; reading and writing Uguisu's tags parses no properties (`read_properties(false)`), so a malformed audio stream is never walked there; only an import reads a foreign file's audio properties, read-only and without cover art; a file that cannot be parsed is a **result** (`tags_unsupported`, HTTP 422), not a crash and not a failed batch.

Writing is where the real risk is, and the control is structural rather than careful: **Uguisu never modifies the only copy of a file.** A tag write copies the artifact into `.uguisu/tmp/`, writes the tags into the copy, re-opens and re-reads it, hashes it, and only then renames it over the original. `clippy.toml` forbids every `lofty` method that writes a file by its path — `TagExt::save_to_path` and `remove_from_path`, `AudioFile::save_to_path` and `TagType::remove_from_path` — at the workspace level (`disallowed_methods = "deny"`), so the in-place API cannot be reached by accident — `uguisu_metadata::write_tags` takes a path and opens it for lofty's handle-based `save_to`; the engine's only caller hands it the `.uguisu/tmp/` copy (`tagging.rs`), so the copy rule lives in the engine, not in a type. A write starts from a clone of the tag already in the file and touches only the thirteen managed keys, so a publisher's lyrics and ReplayGain values survive; its cover survives `fill_missing`, while `sync` with stored artwork replaces the front cover (on MP4, every `covr` image) and records only its type, size and SHA-256 in `original_tags`. Cover bytes are validated by signature before they are embedded. `tag_state = pending` is committed before the first byte moves, so a crash mid-write is recoverable by hashing (§4.3 of `STATE_MACHINES.md`) rather than by guesswork. Fuzz targets for the tag and feed parsers remain planned (Phase 11).

### 3.4a The web UI and the bytes it is served

**Phase 8 (as built).** A browser now renders feed content and plays archived files from the same origin as the API, which adds two things worth stating (ADR 0031, ADR 0032, ADR 0034; `docs/WEB_UI.md` § Security).

*Threat:* a podcast title or a set of show notes containing markup or script. Feed text is untrusted input that reaches the DOM.

*Controls:* every field is rendered as text, and the three that become links (an episode's page, on its own page and in a podcast's episode list; a podcast's website; a directory result's website) do so only when they are `http` or `https` (`web/src/lib/links.ts`), so a `javascript:` link from a feed is never offered. The UI reads `description_text`, never `description_html`, and there is no `{@html}` anywhere in `web/src` — a grep is the whole audit. Svelte escapes interpolated text by construction, so injection needs a deliberate opt-out that does not exist in the tree.

*Threat:* an archived file served back as something the browser executes. A publisher controls the `Content-Type` Uguisu recorded, and an HTML error page saved as an episode would be same-origin script.

*Controls:* the recorded type is never echoed. It is mapped to a container and back to the single type Uguisu publishes for that container; anything unrecognised becomes `application/octet-stream`, and every response carries `X-Content-Type-Options: nosniff`. Header injection cannot survive the round trip because the served value is one of thirteen media types or `application/octet-stream`.

*Threat:* a request path reaching a file outside what it may read — either the media root or the web directory.

*Controls:* both use `uguisu-archive`'s path machinery (§3.2), not a second implementation: `RelativePath::parse`, then `resolve_checked`, then `symlink_metadata(…).is_file()`. The media and artwork routes take an id and read the path from a record, so no caller names a path; there is deliberately no `GET /file?path=…`. The media route additionally refuses a record under the reserved control directory or naming a sidecar. The SPA handler does not percent-decode the request path, which removes the decode-then-traverse class entirely. An error message names only the relative path; the absolute one goes to the log. Traversal and symlink-escape cases are regression-tested in `crates/uguisu-server/tests/{media,web}.rs` (the symlink cases on Unix only); `scripts/e2e.py` sends three traversal paths to the shipped binary's SPA handler.

*Phase 9 added the authentication this section said was missing.* Every byte route is a `Read` and needs a credential; the path machinery in front of it did not change; its regression tests in `media.rs` and `web.rs` run with authentication off, and `auth.rs` `media_and_artwork_bytes_need_a_credential` proves the credential is checked first, with and without `Range` (§3.5, ADR 0036).

### 3.5 Authentication and sessions

**Built in Phase 9** (ADR 0035, ADR 0036). Authentication is off until a password is set and required once one is; on a loopback-only install it is optional, and off loopback it is a startup requirement (§3.6).

*Threat:* unauthenticated access, credential stuffing, CSRF from a malicious site against the local server, credentials in a URL or a log.

*Controls:*
- One operator identity: username plus an **argon2id** hash, 64 MiB / 2 passes / 1 lane, **measured at 101.6 ms** per verification (`docs/benchmarks/2026-09-22-phase9.md`). Set with `uguisu auth set-password`, from the terminal without echo or from stdin when there is no terminal — never from an argument or an environment variable. Hashing runs on `spawn_blocking` behind a two-permit semaphore, so a flood cannot commit unbounded memory or stall the runtime.
- Cookie sessions: `uguisu_session`, 256 random bits, `HttpOnly`, `SameSite=Lax`, `Path=/`, `Secure` only when `UGUISU_AUTH_COOKIE_SECURE=1` (or `--cookie-secure`) is set. Uguisu does not terminate TLS and never infers HTTPS from a request or a header. The database holds only a SHA-256 digest, so a stolen database cannot be replayed as a session. Idle expiry 7 days, absolute 30 days, refreshed at most hourly; pruning runs in the maintenance tick and reports `sessions_pruned`.
- CSRF: a mutating request authenticated by the cookie must echo the session's token in `X-Uguisu-CSRF`, compared with `Secret::ct_eq`, or it is 403 `csrf_required`. Bearer principals are exempt — no browser attaches `Authorization` by itself.
- Cross-site changes, with or without a password: a request that is not `GET`, `HEAD` or `OPTIONS` and names another site in `Origin` is 403 `forbidden` before authentication is resolved (ADR 0058). With authentication off it is the only thing that stops a page's form post to a body-less mutation; a request without `Origin` (the CLI, curl) passes.
- API tokens for CLI and automation: 256 random bits, stored as a digest, shown once, two scopes (`read`, `write`), revocable with the row kept so a listing can say it was revoked. Carried as `Authorization: Bearer`. A `read` token at a mutation is 403.
- **No credential in a URL, on any route.** There is no query parameter for a token: the middleware reads a credential only from `Authorization` and `Cookie`, and `auth.rs` `query_token_is_refused` shows a valid secret in five likely query names is refused. The browser uses a cookie precisely so `<audio src>` and `EventSource` need no header.
- One message for a wrong password and for an unknown user, and an unknown user is still verified against a dummy hash, so the timing does not answer the question either.
- Login rate limiting: ten failures per peer per five minutes plus a global hundred, then 429 with `Retry-After`. In memory, bounded to 1 024 peers. The peer is the socket's, or behind a proxy named with `--trusted-proxy` the client its `X-Forwarded-For` names, read from the right (ADR 0062, `docs/DEPLOYMENT.md`).
- Secrets never reach a log or a response: `Secret<T>` has no `Debug` that prints, the password never appears in `--help`, status, JSON or an error, and `scripts/e2e.py` greps everything the server and the CLI wrote for the password and both token secrets.
- **A log never carries a URL's userinfo, query or fragment.** A private feed or a signed enclosure keeps its credential there, under any parameter name, so a log line keeps scheme, host, port and path and writes `[redacted]` for the rest. Every log site formats a URL, or an error that quotes one, through `uguisu_core::redact::urls`. API responses, events, the database and a command's own output keep the URL whole; `crates/uguisu-cli/tests/logs.rs` asserts a feed's `?token=` reaches no log line of a `podcast add`, of a failed refresh whose error body echoes it, or of a search that quotes it.

### 3.6 Network exposure

**Built in Phase 9** (ADR 0037).

- Default bind `127.0.0.1:8484`. A bind that is not loopback **with no password set is a startup failure**, exit code 12, checked before the listener opens and before the workers start. `UGUISU_AUTH_ALLOW_INSECURE_EXPOSURE=1` is the deliberate override and logs one `WARN` naming the address and `auth = "disabled"`. Loopback is decided on the canonical address, so `::ffff:127.0.0.1` counts.
- Security headers on every response: `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`, and on `text/html` a CSP whose every executable directive is `'self'` — `script-src`, `style-src`, `connect-src`, `media-src`, `font-src`, `form-action` — with `object-src 'none'`, `base-uri 'none'` and `frame-ancestors 'none'`. `img-src` is `* data:`, the one open directive: a podcast whose artwork Uguisu has not fetched falls back to the URL its feed published, artwork fetching is off by default, and an image cannot execute. No `unsafe-inline`.
- **No CORS.** No response carries an `Access-Control-*` header, and no `OPTIONS` is answered as a preflight. On an API route it is refused in the standard envelope: 405 with authentication off, 401 `unauthenticated` once a password is set (a preflight carries no credential). Outside `/api` it gets the SPA shell. The SPA is same-origin by construction.
- **Residual: DNS rebinding with authentication off.** A rebinding page is same-origin with the name it rebinds, so the `Origin` check (§3.5) does not see it. While no password is set, any website the operator visits can read the library, start jobs such as imports, backups and vacuum, and set the first password, which takes the install over. A password closes it, and `serve` logs a `WARN` at startup while none is set; a `Host` allowlist is not built (ADR 0058).
- No TLS termination. **Only `X-Forwarded-For`, and only from a proxy the deployment names** (`--trusted-proxy`, ADR 0062), is read, from the right, to give the login limiter and the logs the client's address; every address as a proxy (`0.0.0.0/0`) is refused, and the desktop shell's exchange checks the socket regardless. No header is trusted for the scheme or the host: the cookie's `Secure` flag is an explicit setting (`docs/DEPLOYMENT.md`).

### 3.6a The desktop application

**Built in Phase 9a** (ADR 0041, ADR 0042, ADR 0044).

*Threat:* another local process, or a page in some other WebView, using the embedded server or the shell's native commands; a launch credential leaking; the sandbox widened to reach the archive.

*Controls:*
- The embedded server always requires authentication, even before a password exists, so a desktop install is never an anonymous API on loopback. It binds `127.0.0.1:0` only, through the same exposure gate as `uguisu serve`.
- The per-launch `write` token lives only in the shell's memory, is handed to the page once, is exchanged for an ordinary `HttpOnly` session by `POST /api/v1/auth/exchange` (token principals only, loopback peers only, read from the socket), expires after an hour and is revoked at shutdown. `desktop_smoke.py` fails if a 64-hex secret appears on either output stream.
- IPC is granted at runtime to the `main` window at exactly `http://127.0.0.1:<port>`: seven commands, no shell, filesystem, process or opener-URL permission, no wildcard. `reveal` takes archive-relative paths only and resolves them with `resolve_checked`.
- The Flatpak has no `--filesystem` permission; a folder outside its data directory is reached only through the portal, and `check-desktop-layout.py` fails if one is added.

### 3.7 Discovery providers

*Threat:* a provider returns a feed URL pointing at an internal host, misleading metadata, or floods with results.

*Controls:* provider output is untrusted input: all URLs go through the SSRF policy at resolution time; result counts are capped (at most 100 per search), and each provider response body is capped at 2 MiB. Individual fields are not truncated.

*Correction (Phase 9).* This section used to promise provider credentials "stored in the DB encrypted-at-rest with a key derived from a server secret file (`/data/secret.key`, 0600)". There is no such file and there is nothing to encrypt: both Podcast Index keys are **non-persistable** settings (ADR 0028), so they only ever exist in the environment and never reach the database. The `SettingSpec` that marks them secret is also what redacts them from `GET /api/v1/settings` and `config list`, in `value`, in `stored` and in the rejected and unused lists. If per-source feed credentials are ever stored, encryption at rest becomes a real requirement and gets its own ADR.

### 3.8 Resource exhaustion

*Controls (Phase 9 adds the request-body limit's test, the login limiter and the session-write rule):* bounded concurrency for refreshes (`UGUISU_FEED_REFRESH_CONCURRENCY` and per-podcast coalescing, so a burst of refresh requests for one feed costs one fetch), downloads (`UGUISU_DOWNLOAD_GLOBAL_CONCURRENCY` with a per-host limit) and provider calls; a verification checks one file at a time, but concurrent verification runs are not limited, so a `write` credential can start several full-hash scans at once, a free-space check before each attempt and `ENOSPC` handling that pauses the whole queue persistently (`UGUISU_DOWNLOAD_MIN_FREE_BYTES`), a media size cap (`UGUISU_DOWNLOAD_MAX_BYTES`, 8 GiB) on the whole file, enforced while streaming and, for a resumed transfer, on the bytes already on disk plus the rest, so an oversized body is never held in memory or completed, an idle timeout per chunk, bounded attempts with exponential backoff and a persisted `next_attempt_at` (no retry storm after a restart), DB busy timeouts, request body limits on the API, pagination caps (every paged route 500, events 1 000; ADR 0040), axum's 2 MB request-body limit — answered as 413 `payload_too_large` and covered by a test rather than asserted in prose — ten login failures per peer per five minutes plus a global hundred, argon2 hashing bounded to two concurrent verifications, and a session's `last_seen_at` refreshed at most hourly so an authenticated read does not queue behind the single writer. Progress events are throttled and never persisted, so a large transfer cannot grow the event log.

### 3.9 Data loss (the archive is the crown jewel)

*Controls:* atomic finalization (Phase 4: a final path is only ever created from a complete, hashed `.part`, after `sync_all`, by a hard link that never replaces an existing name (check-then-rename only where links are unsupported) and, on Unix, a directory fsync); no automatic deletion — an occupied target ends the job `failed(target_exists)`, an unknown `.part` is reported as an orphan and a file that vanished is reported by a deep reconcile, never recreated silently; verification never mutates; the two commands that delete library rows nothing can recreate take an explicit flag and are logged as events: `episode resolve --same` as `episode.duplicate_resolved` (ADR 0051), and `podcast remove --yes`, which keeps every file, as `podcast.removed` (ADR 0055). `uguisu db backup` writes a consistent copy of the database without stopping the server; through the API it goes only to the server's own `backups/` directory, so a credential cannot make the server write a file anywhere else (ADR 0056).

**Uguisu adds the other half of this: the archive stops depending on the database.** Every media file has a sidecar beside it and every podcast a `sha256sum -c` manifest, so after a lost database, adding the feeds again and running `archive reconcile --rebuild` restores every archive record (a rebuild never invents a podcast or an episode) and an archive copied to another machine explains itself. Rebuilt records come back `unchecked`: a sidecar is metadata, not evidence.

The no-deletion rule is stated once and holds everywhere in Phase 6: leftover scratch files, unknown sidecars, unknown media, a foreign file at a target path, an import source, a superseded artwork image and a conflicting record are all **reported and kept**; `archive orphans` is the report for the first three (ADR 0051). Import copies and never moves, opens the source read-only, and refuses to overwrite an existing Uguisu file. Tag writing never modifies the only copy (§3.4). There is no `.bak`: the sketch named one, and a copy-then-rename leaves no moment at which a `.bak` would exist — the original *is* the backup until the replacement is proven readable.

### 3.10 Supply chain

*Controls:* `cargo deny` for advisories and licenses in CI; `check.py audit` runs `pnpm audit` over the web dependencies, build tooling included, on request (it asks the registry, so CI does not run it; its first run, on 2026-10-04, found six advisories in `devalue` 5.9.2, which `svelte` pulls in, and the lockfile moved to 5.9.4; on 2026-10-06 it found GHSA-68fv-2mgg-jv7q in `source-map-js` 1.2.1, which `postcss` and `jsdom` pull in, and the lockfile moved to 1.2.2); `Cargo.lock` and `pnpm-lock.yaml` committed; minimal dependency set. The Docker image builds from base images pinned by digest, and `scripts/check-docker.py` refuses one that is not (ADR 0061). Not built: release binaries with an SBOM (post-v1).

The desktop workspace has its own `desktop/deny.toml`, resolving only the two shipped targets; besides the `paste` advisory below it accepts six `unmaintained` ones, each reached only through the Tauri/GTK stack and listed with its path. The five AppImage build tools the bundler would fetch unverified are pinned by SHA-256 in `scripts/appimage_tools.py`, and a changed hash or a bundler download fails the build (ADR 0043).

Phase 6 added three crates and deliberately declined a fourth: `lofty` (tags), `walkdir` (scanning) and `strsim` (already in the tree for discovery, reused for matching). The `image` crate that `ARCHITECTURE.md` originally named for artwork was **not** added: Phase 6 neither decodes nor resizes an image, so all that is needed is a twelve-byte signature check, and a decoder is a large attack surface to take on for something no feature asks for (ADR 0026).

**One accepted advisory** in the root workspace: `lofty` depends on `paste`, which is **unmaintained** (RUSTSEC-2024-0436). It is not a vulnerability and there is no upgrade: 0.25.4, the latest `lofty` release (checked 2026-10-04), still uses it, and upstream declined replacing it (lofty-rs PR #625). Two ways around it were rejected: `unmaintained = "workspace"` would silence every transitive unmaintained crate, and a `[patch]` onto a fork breaks `unknown-git = "deny"` and adds a fork to maintain. `paste` is a proc-macro: it expands at compile time and ships no code in the binary, so the exposure is the build, not the artifact. It is listed in `deny.toml` with that reasoning rather than silently allowed, and the entry is to be removed as soon as `lofty` drops the dependency. Everything else in `cargo deny check` — advisories, bans, licences, sources — passes with no exceptions table for licences at all.

## 4. Out of scope (v1)

- Multi-tenant isolation (single admin).
- Protection against a malicious local user on the desktop machine.
- DRM or access-controlled feeds beyond what the feed URL itself carries: userinfo, which the HTTP client sends as Basic auth, or a token in the query. No per-source credentials in v1; storing any needs encryption at rest and its own ADR (§3.7).
